# PRD 对照查漏报告 — 设计师前端页面 vs TinyHabitat-PRD

> 隔离声明：本报告仅对照 `<USER_HOME>/Desktop/设计师前端页面` 一个前端项目的实物呈现与其自带的产品文档 `TinyHabitat-PRD.md`。不涉及、不引用、不猜测任何其它项目或后端形态。凡涉及数据/生成/持久化能力，一律用"该功能需要一个能 X 的服务"的中立语言。

## 0. 方法与结论

- **对照对象**：PRD 全文 15 节 × 已提取的 6 分片功能点索引（shard-01..06）+ 直接核对 `src/main.jsx:28-76` 数据数组。
- **提取覆盖面结论**：**前端实物上"能看到、能点、能读"的组件与文案，6 个分片已 100% 覆盖，无组件级遗漏**。20 个组件全部落在分片里，两处无 onClick 按钮、写死适配评分、假分页等实现真相也都被记录。
- **本报告的"缺口"性质**：绝大多数不是"分片漏提取了页面上存在的东西"，而是**「PRD 描述了但前端实物没有做/做得不一致」**——即 PRD 要求 ⊃ 前端实现。这类缺口按"PRD 出处 + 前端实物现状"成对列出，供判断 MVP 验收差距。
- **另一类是 PRD 与实物的数据/文案不一致**（同一事物两处说法不同），单列一节。

## 1. PRD 有要求、前端实物未实现（真缺口）

### G1. 宠物档案缺「性格标签」与「居住环境类型」两个字段（高）

- **PRD 出处**：§6.3 宠物档案字段明确列出 6 项：`宠物名字 / 品种 / 照片 / 体型大小 / 性格标签 / 居住环境类型`；§9.1 PetProfile 数据草案含 `traits`（性格标签数组）与 `habitatType`。
- **前端实物**：`PetCreatorSection`（shard-03）只提供 4 个输入：名字（input）、物种（按钮行）、体型（range）、照片（file）。**没有任何"性格标签"选择/输入控件，也没有"居住环境类型"字段**。性格标签只在 `IntroSection` 的写死示例卡"Nomi 的档案"里以静态文字出现（shard-05 §1.2），不是用户可填写的档案字段。
- **性质**：PRD 要求的档案字段 > 前端可输入字段。分片提取无误（PetCreator 确实只有这 4 项），缺口在实现侧。

### G2. 「选择物种后，下方推荐对应标品模块」未接线（高）

- **PRD 出处**：§6.2 宠物品种选择功能要求最后一条："**选择物种后，下方推荐对应标品模块**"；§5.2 标品社区流程同样隐含按物种推荐。
- **前端实物**：数据层已具备该联动的全部素材——`species` 数组每个物种都带 `modules` id 列表（`main.jsx:28-34`，如花枝鼠关联 6 个模块、守宫关联 5 个），但 `ModuleCommunitySection`（shard-04 §4.4 与 §7-5 明确记录）**只是纯罗列全部 13 个模块 + 展开/收起两态，未接入任何"按当前选中物种筛选/推荐"的交互**。切换物种不会改变下方模块列表。
- **性质**：数据结构已就绪、UI 联动缺失。这是 PRD 核心流程的一环，落差明确。

### G3. 场景包无「进入定金支付 / 选购加入」入口（高）

- **PRD 出处**：§6.7 整装场景包功能要求最后一条："**允许用户从场景包进入定金支付**"；§5.1 主流程第 9-11 步（选择场景包 → 展示报价 → 支付定金）。
- **前端实物**：`ScenePackSection`（shard-05 §4.2）三张卡片是纯展示——有效果图、标签、简介、起售价，但**卡片本身无任何 onClick、无"加入""选购""支付定金"按钮**，停留在营销展示层，不能从场景包发起任何下单/加入动作（与 `ModuleCard` 的"加入 3D 场景"可交互形成对比）。
- **性质**：PRD 明确要求的交互入口在实物上完全缺失。

### G4. 「习性与材料建议」不随所选物种联动（中）

- **PRD 出处**：§6.4 习性与材料建议，目标是"让用户觉得平台懂宠物"，并给出花枝鼠的喜好/风险/推荐材料/不建议材料四类具体建议；§5.1 主流程第 4 步"系统展示该品种的习性、风险和材料建议"。
- **前端实物**：习性建议出现在两处，都不联动：
  - `IntroSection` 习性面板（shard-05 §1.3）——写死一套花枝鼠通用规则（喜好/风险/材料三条），**无论选哪个物种都不变**。
  - `species` 数组虽给每个物种带了 `traits` + `material` + `habitat`（轮播卡片 shard-02 会随物种显示），但**只有"喜好/材质/栖息地"三类，没有 PRD §6.4 强调的"风险点"和"不建议材料"**这两类安全信息。
- **性质**：PRD 要求「按物种展示差异化的习性+风险+材料建议」，实物只做到轮播卡展示喜好/材质，且核心的"风险 / 不建议材料"仅以花枝鼠写死通用文案出现，不随物种变化。§12.2 产品逻辑验收"用户能看到不同物种有不同习性与材料建议"未真正满足。

### G5. 「开始定制 / 创建专属宠物档案」CTA 未导向真实创建流程（中）

- **PRD 出处**：§5.1 主流程第 1→3 步（进入首页 → 选择品种 → 创建档案），§6.1 主 CTA"开始定制"。
- **前端实物**：shard-01 §2.3 与 shard-02 §5 均记录——首屏"开始定制"按钮、轮播下方"创建专属宠物档案"卡片，onClick 全部绑定 `() => setDrawerOpen(true)`，**打开的是同一个只读介绍抽屉 `DetailDrawer`，不滚动/不跳转到真正的 `PetCreatorSection` 表单**。文案暗示"进入定制流程"，实际只展示说明。
- **性质**：文案期望 > 已绑定行为的落差。不影响功能存在（创建器在页面下方真实存在），但主 CTA 的引导链路断了。

### G6. AI 效果图 / vibe 生成链路全段悬空（中，PRD 已自认 Demo 态）

- **PRD 出处**：§6.5 上传与 Vibe（上传笼箱照片 + 上传宠物照片 + 输入自然语言 vibe + 点击生成）、§6.6 AI 效果图（改造前 4:3 / AI 改造后 16:9 / 小红书分享图 3:4）。
- **前端实物**：
  - `UploadVibeSection`（shard-05 §2）——两个上传位是 `AssetPlaceholder` 纯占位、**无真实 `<input type="file">`**；prompt 是写死 `<span>` 不可编辑、**非输入框**；"生成"按钮**无 onClick**。
  - `RenderSection`（shard-05 §3）——三张效果图全是 `AssetPlaceholder` 占位。
- **性质**：PRD §6.5 已自陈"Demo 阶段为静态演示"，故属"预期内的占位"。但需注意：PRD §6.5 要求上传"当前笼箱照片"**和**"宠物照片"两处上传；实物这两处上传位都无真实上传能力（只有 `PetCreatorSection` 那处宠物照片上传是真的）。分片提取无误，此处作为"PRD 功能范围 vs 当前完成度"记录。

### G7. 报价 / 重量 / 生产周期不随用户实际选择计算（中，PRD 已自认预留）

- **PRD 出处**：§6.9 3D 模型与打印报价（展示材料选项、重量估算、生产周期、价格区间），报价逻辑示例 PETG ¥0.42/g、PLA+ ¥0.28/g、后处理 ¥49 起、周期 2-4 天。
- **前端实物**：`ManufacturingSection`（shard-06 §1）——材料价目表三行、报价区间 ¥399-¥899、预计 1.8kg/2-4 天**全部写死**，与用户在 shard-04 实际选的模块组合无任何数据绑定；`EnvironmentPreviewSection` 的"生成场景报价"按钮**无 onClick**（shard-04 §5.6）；"适配评分"恒为 92%（写死，shard-04 §5.3）。
- **性质**：PRD §6.9 报价逻辑示例的数值与实物写死值一致（¥0.42/¥0.28/¥49/2-4天 完全对上），属"示例数据落地"。缺口在于「报价不随选择动态计算」+「生成场景报价按钮未接线」。属 MVP 预期内占位，但需在验收时标注为未闭环。

### G8. 首单礼物「挂件绑定宠物档案」未体现（低）

- **PRD 出处**：§6.10 首单礼物功能要求"挂件绑定宠物档案""可作为用户分享点"。
- **前端实物**：`GiftSection`（shard-06 §2）是纯图文展示（真图 `gift-keychains.jpg` + 说明文案），**无任何与宠物档案数据的绑定、无分享按钮**。
- **性质**：PRD 要求的"绑定档案 / 分享点"在实物上仅停留在文案描述，无交互挂载点。属营销展示卡，MVP 可接受，记录备查。

### G9. 订单流程条无「当前进度」状态（低）

- **PRD 出处**：§7 订单闭环（Demo 链路 8 步 / 真实链路 11 步）。
- **前端实物**：`OrderFlowSection`（shard-06 §3）八步流程条纯静态展示，**不高亮当前步骤、不可点击跳转、无状态机驱动**。
- **性质**：PRD §13 V0.1 静态 Demo 明确本阶段是"静态报价逻辑/静态流程"，故属预期内。记录为"闭环仅展示、未驱动"。

## 2. PRD 与前端实物的数据/文案不一致（同一事物两处说法不同）

### M1. 「首批标品 8 项」名称与实物 13 模块完全不同（中）

- **PRD 出处**：§6.8 首批标品列出 8 个具名 SKU：`奶酪洞穴窝 / 双通道连接管 / 圆角攀爬平台 / 食盆固定座 / 守宫湿躲屋 / 宠物姓名牌 / 晒背平台 / 荒漠岩石斜坡`；§9.2 ProductModule 示例 id=`cheese_nest` 名"奶酪洞穴窝" ¥89。
- **前端实物**：`modules` 数组（`main.jsx:36-50`）是 **13 个模块，名称全不同**：奶酪软垫小床 / 香蕉软垫小床 / 夹层香蕉垫 / 悬挂藤篮阶梯 / 奶酪洞洞层板 / 藤蔓觅食托盘 / 奶酪收纳高柜 / 多巴胺攀爬站 / Z字吊桥梯 / 星月魔法躲屋 / 星桥拱门躲屋 / 蘑菇攀爬树 / 星旋攀爬立柱。**PRD 的 8 个 SKU 名一个都没出现在实物里**（"奶酪洞穴窝"≠"奶酪软垫小床"，"守宫湿躲屋"≈"星月魔法躲屋"但名不同）。
- **性质**：SKU 目录已迭代过一版，PRD §6.8/§9.2 是旧命名，实物是新命名。数据源单一真相已是 `modules` 数组，PRD 副本过期。分片 shard-04 提取的是实物新数据，无误。

### M2. 场景包只有 3 个但 PRD 主流程物种举例更宽（低）

- **PRD 出处**：§5.1 主流程举例物种为"花枝鼠、仓鼠、豹纹守宫、睫角守宫、鬃狮蜥"（5 类，且含仓鼠/守宫细分/鬃狮蜥）。
- **前端实物**：`species` 数组是 `花枝鼠 / 守宫 / 蛇 / 鹦鹉 / 蜘蛛`（5 类，但**是蛇、鹦鹉、蜘蛛，而非 PRD 的仓鼠、豹纹守宫、睫角守宫、鬃狮蜥**；守宫只有一个笼统条目不分豹纹/睫角）。§6.2「首批物种」列表同 §5.1（花枝鼠/仓鼠/豹纹守宫/睫角守宫/鬃狮蜥）。
- **性质**：物种清单在 PRD（爬宠/小宠细分为主）与实物（花枝鼠+蛇/鹦鹉/蜘蛛+笼统守宫）之间已漂移。分片 shard-02 提取的是实物 5 物种，无误。PRD §6.2 首批物种列表已过期。

### M3. 装扮「适配规则」PRD 要求校验、实物无限制（低）

- **PRD 出处**：§6.3 宠物档案"支持装扮商品添加"；能力地图卡片文案（`workflowCards`）"每个穿戴物都有价格、适配规则和预览中的位置反馈"。
- **前端实物**：`wearableItems` 每件带 `fit` 字段（如"花枝鼠 / 鹦鹉"），但 shard-03 §10 记录——**代码未见任何基于 `fit` 的校验/禁用逻辑，选了不适配物种仍可勾选任意装扮**。
- **性质**：文案承诺"适配规则"，实物只展示 fit 文字不做限制。低优先级，记录备查。

### M4. 站内标题「TinyHabitat AI」vs 资产命名「PetScape」（低，已知命名漂移）

- **出处**：`index.html:5` `<title>TinyHabitat AI</title>` + logo 文件 `petscape-logo.png` + 多处 CSS class 前缀 `petscape-`；PRD 文件名 `TinyHabitat-PRD.md`、正文产品名"TinyHabitat AI"。
- **性质**：`_map.md` §5-4 已判定为命名漂移而非两个项目，功能无影响。此处仅归档，不作为功能缺口。
