# ADR-0005：OSS 私有对象存储与客户端直传

- 状态：Accepted（2026-07-17 终审通过）
- 决定日期：2026-07-17
- 适用阶段：Phase B 起

## 背景

PetScape 需要保存用户上传图片、AI 生成图片、GLB、STL、G-code 和订单证据。正式资产不能继续放在 Web 公共目录，也不能让“知道路径”成为访问权限。Web、未来 App 和微信小程序需要在不消耗 Web 服务器大文件带宽的前提下上传与下载。

资产元数据、归属、版本和业务状态由关系型数据库拥有；对象存储只保存二进制内容和必要对象属性。

## 决定

采用阿里云 OSS 私有 Bucket。第一阶段不接 CDN，不允许公共读写。

对象 key 使用职责前缀分区：

- `uploads/raw/`：用户上传原始文件；
- `uploads/generated/`：生成图片及其他中间输出；
- `assets/3d/`：GLB、STL、G-code 等 3D 资产；
- `orders/evidence/`：订单、售后和履约证据。

具体 key 必须包含不可猜测的资产标识，并由数据库中的 Asset 记录保存 owner、项目/订单归属、内容类型、大小、校验值、版本和 OSS 引用。客户端提交的文件名和 MIME 类型不能直接成为可信元数据。

访问方式：

- 读取与单次小文件写入由服务端鉴权后签发短 TTL 的 OSS V4 签名 URL；
- 服务端使用最小权限 RAM 身份或实例角色签名，长期主账号密钥不下发客户端；
- Web 大文件直传由服务端在授权后签发限定 Bucket、前缀、操作和时长的 STS 临时凭证，客户端使用官方 Browser.js SDK 执行 multipart/resumable upload；
- 上传时间可能超过凭证有效期时，客户端必须支持凭证续期和安全恢复，不能简单延长为长期凭证；
- Worker 生成的资产由 Worker 的受限 RAM 身份直接上传 OSS，不经浏览器 STS；
- 上传完成后由服务端校验对象 key、大小、哈希/ETag 和所有权，再把 Asset 状态推进为可用。

生命周期策略：

- 草稿或临时内容按前缀及必要标签设置到期清理；
- `orders/evidence/` 不进入普通草稿删除规则，可按合规和运营要求转低频或归档存储，但不自动删除；
- 未完成 multipart upload 必须设置终止与清理策略；
- 具体保留天数仍是模块策略，不在本 ADR 固定。

微信小程序当前只承诺官方支持的小文件直传路径。官方没有现成的微信小程序分片上传方案；大文件必须在后续客户端设计中选择自研分片、限制小程序入口、服务端生成或引导 H5/App，不在 Phase B 假装已经解决。

## 关键理由

- OSS 与 ECS、RDS 同属阿里云边界，便于私网、RAM、审计和统一运维；
- 私有 Bucket + 服务端授权签名使资源访问服从应用层权限，而不是公开 URL；
- V4 签名 URL 适合一次性读写，客户端不持有长期密钥；
- STS + multipart 适合数十至数百 MB 的 3D 大文件，并允许浏览器断点续传；
- 客户端直传避免 Web 容器代理大文件带宽和内存，同时保留应用层对 key 与权限的控制；
- 前缀生命周期规则直接表达草稿与订单证据不同保留级别；
- 初期访问量不需要 CDN，避免私有回源鉴权与缓存权限复杂度。

## 放弃的备选

### ECS 本地磁盘或 `web/public/`

无法跨重建可靠恢复，容易产生公开访问和多进程一致性问题，也会把应用部署与用户数据绑在单机。

### 公共读 Bucket

无法满足用户资产归属、订单证据和短期授权要求，泄露风险不可接受。

### 所有文件经过 Web 服务器中转

实现直观，但会放大 Web 带宽、内存、超时和扩缩容压力。服务端仍负责授权与完成确认，不需要转发全部字节。

### 只使用长期 AK/SK 的客户端 SDK

会向客户端暴露长期凭证，明确禁止。

### 第一阶段接入 CDN

当前不是公共高并发分发场景。私有 Bucket 的 CDN 回源鉴权与缓存失效会增加复杂度，待真实重复访问和带宽数据证明需要后再评估。

### 自建 S3 兼容对象存储或其他云厂商

增加单机耐久性责任或跨云网络边界，与已确认的阿里云托管策略不一致。

## 已知代价与风险

- STS 与签名 URL 有双重有效期，长时间分片上传可能因凭证过期中断；
- 客户端暂停、续传和凭证刷新需要保存 upload ID 与 checkpoint，并防止越权恢复；
- 未完成 multipart 会持续占用存储并产生费用；
- 生命周期规则误配可能删除仍被项目或订单引用的资产；
- OSS 对象版本控制与应用层资产版本号的职责尚需验证，不能同时无规则使用两套版本；
- 微信小程序大文件分片没有官方一站式实现，是明确产品能力 gap；
- App 原生 SDK 的断点续传能力尚未核实；
- 签名 URL 一旦泄露，在 TTL 内仍可被持有者使用，因此 TTL、操作方法和对象范围必须最小化；
- 暂不接 CDN 意味着所有下载走 OSS 源站，后续需以真实流量和体验数据重评。

## 验证条件

Phase B 私有资产链必须关闭以下条件：

1. 在目标 `ali-oss` 版本中验证 `signatureUrlV4`、STS、Browser.js multipart 和 checkpoint API；调研未核实的最低版本号必须通过锁定版本和自动测试解决；
2. 用真实私有 Bucket 验证未授权请求失败、签名 URL 到期失效、方法/对象不可越权以及不同用户不能互访；
3. 验证 STS RAM Policy 只能访问当前用户获准前缀和操作，并测试凭证过期后的续期与断点恢复；
4. 对大文件执行暂停、断网、刷新页面、凭证到期和完成回调测试，证明不会重复创建 Asset 或留下错误可用状态；
5. 明确 ETag、内容哈希和 multipart ETag 的校验策略，不把 multipart ETag 误当作通用 MD5；
6. 在启用生命周期规则前使用测试 Bucket 演练前缀和标签过滤，证明草稿可清理、`orders/evidence/` 与已付款订单引用不会被删除；
7. 配置并验证未完成 multipart 的清理规则与告警；
8. 决定 OSS Object Versioning 与应用层不可变 asset version 的职责；未决定前，以新 object key + 数据库版本记录为默认，不覆盖历史承诺对象；
9. 在微信小程序实现前复核 `wx.uploadFile` 当前精确限制和阿里云官方能力；若无成熟分片方案，必须由产品明确大文件降级路径；
10. 在 App 实现前分别验证 iOS/Android 官方 SDK 的 multipart、断点续传和凭证刷新；
11. 上线前用阿里云官方价格计算器复核存储、请求、外网流量和归档恢复费用；调研中的社区价格只作量级参考。
