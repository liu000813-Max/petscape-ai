# 我的、设置与五栏导航验收

## 用户确认与范围

用户于 2026-11-23 确认白底黑字、少量粉色的五栏方案：新增“我的”（身份卡、横滑宠物卡、养护／栖境入口、建议卡）和设置（微信权限、刷新资料、数据说明、关于）；底栏依次为首页、知识、宠物、社区、我的，中央圆形宠物按钮突出。其余草图模块不在本轮范围。

## 实现

- `pages/me` 使用现有会话与 `listPets` 读取本人宠物，展示上传照片或物种备用图。点击各宠物卡进入对应档案；新增、全部档案、养护、栖境、知识与设置入口均连接既有或本轮真实页面。
- 身份显示默认“养宠人”，数量来自读取结果；加载或失败显示“—”，不把失败说成零宠物。清空旧列表并校验请求序号，防止较早读取覆盖当前结果。
- `pages/settings` 在用户点击时调用 `wx.openSetting`；刷新只执行现有读取及会话恢复，不新增删除或清空缓存按钮。失败保留分类诊断。版本来自 `getAccountInfoSync().miniProgram.envVersion`，账号模式沿用项目配置，分别显示测试号与开发预览。
- `custom-tab-bar` 与原生 `app.json` 保持五个路由一致；选中态由实际路由和每页 `onShow` 同步。切换失败保留实际页面；忽略重复点击及未知路由。
- 首页体重、养护、设备弹窗打开时隐藏该页底栏，并在处理函数再次阻止隐藏状态切换。关闭恢复底栏；本轮不改变保存接口与现有写入锁。五个 tab 页预留悬浮栏、中央突出按钮及底部安全区，普通设置页不展示底栏。
- 小图标由 `scripts/build-miniapp-nav-icons.mjs` 从统一线条图生成 PNG；官方编译入口同时编译自定义底栏，避免只检查普通页面。

- 官方编译器通过 16 个 WXML 和 17 个 WXSS，包括新增两页及底栏。原生截图暴露微信默认按钮宽度规则导致设置文字挤压，使用页面限定选择器修正后重新编译、截图和量测。
- 开发者工具恢复后，“我的”真实读取成功，共 2 份档案，读取错误为空；照片正常显示。设置刷新真实读取成功，共 2 份，非 mock，不执行数据写入。
- 官方自动化 SDK 调用各栏实际切换处理函数，等待目标路由稳定后，知识、宠物、社区、我的分别与底栏选中态一致；首页亦核对一致。宠物卡原生事件进入 `pet-edit` 且 `isEdit=true`，返回“我的”后选中态正确。
- 首页原生“记体重”事件打开弹窗，底栏 `hidden=true`；此时尝试底栏切换仍停留首页和原弹窗，关闭后恢复。未提交体重或其他业务数据。
- iPhone 模拟器截图检查白底、两列入口、建议换行、圆形中央按钮和底部安全区；页面滚动到底时末尾签名及知识入口均在底栏之上。照片、档案内容与原始截图仅保留仓库外私有证据目录 `petscape-dev-runtime/evidence/me-navigation-2026-11-23`，不提交 Git。
- 生产小程序健康端点 `/miniapp-api/api/healthz` 返回 200。本轮为客户端页面改动，未触发后端发布或迁移。
