# PETSCAPE 首页增量验收

状态：本轮首页实现、开发工具验证和小程序后端发布完成；更新后手机验收待确认。当前运行账号仍是测试号，开发预览不代表体验版或正式发布。

## 授权与范围

- 用户提供六屏线稿，并明确最终目标为整套线稿模块；随后选择白底黑字、官网风格、少量粉色，有宠物即可显示体重，首轮增加切宠、头像和体重并保留其他首页内容。
- 最新范围为“先改首页，其他暂时不动”。本轮以该指令实施首页，不新增头像上传入口、硬件连接、启动引导或个人中心。每次后续界面替换先让用户确认。
- 用户明确要求一个产品经理子 Agent；其职责是只读检查代码、产品边界和实现路径，不扩大修改范围。

## 实现

- 首页横排显示宠物家庭，按 ID 选择宠物，当前头像有粉色描边。已有封面照片优先显示，失效后依次回退物种图、emoji；本轮没有新增图片上传能力。
- 有宠物时显示体重模块：最近值、与上次之差、最近七次柱状记录以及展开式 g/kg 输入。无宠物时保留建档入口。
- 体重以当前宠物 ID 写入原有 care-logs，不新增公开接口或迁移，不部署替换后端。显示范围与数据规则见 [内容规范](../specs/miniapp-content.md)。
- 切换时保存各宠物未提交输入；档案重排继续选择同一 ID，删除的宠物不保留草稿。过时的列表与体重响应不能覆盖较新选择。
- 保存期间锁定其他写入和切换直到刷新结束；模糊失败不自动重复写入，明确成功后的刷新失败不报告成保存失败。

## 第二轮：圆形宠物滑块与档案直达

- 用户明确确认：已建档首页移除黑色“记录宠物的每一天”和横排头像，替换为中间大、两侧小且渐隐的圆形滑块；左右切换后同步下方档案与体重。随后要求点击圆形图像直接进入对应宠物档案。
- 使用原生 swiper，current 按 selectedPetId 从最新列表派生，重排与删除后继续核对身份。单宠只展示真实一只；双宠不循环，首尾仅展示存在的一侧邻居；三宠及以上循环。头像自身的缩放与透明度形成渐隐，不叠加拦截点击的边缘遮罩。
- 每个头像的点击读取自己的 dataset.id，而非当前所选 ID；小档案卡也直接进入当前宠物的既有 pet-edit 页面。跳转前核对 ID 仍在首页本人的列表中，参数编码后传递；服务端原有所有权检查继续生效。
- 保存期间以同尺寸静态当前头像替代 swiper，直到保存和刷新结束；排队的滑动事件不能改变宠物身份。期间不允许打开档案，避免切页与写入冲突。
- 新增三项行为测试先失败，再通过；合计 50 项首页与会话回归通过、零跳过，官方编译通过 13 个 WXML 与 14 个 WXSS，修改测试文件 ESLint 通过。本轮未改业务 API、数据库或体重写入合同，未重复上一轮完整 HTTP 构建。
- 实际开发工具内真实账号与线上 HTTP 验证：原有宠物点击圆形头像进入自己的编辑档案；创建两只独立命名临时测试宠物后，实际 swiper.swipeTo 触发切换，中心宠物 ID、petIndex、原生 current 与下方档案一致，体重读取成功，黑色卡片不存在。
- 双宠情况下实际点击侧边头像，进入该项自己的编辑档案；选择器验收需枚举头像并核对 data-id，不能依赖未验证的复杂选择器。所有本轮新增验收宠物均经既有 DELETE 软删除，只操作测试创建的 ID。
- 三宠静态布局与保存中静态锁定另用显示夹具验收，结束后恢复实际数据；这类截图只证明布局。对应实际导航、滑动、侧边点击与夹具的脱敏回执位于仓库外 wechat-diagnostics/home-carousel-20261116。
- 产品经理子 Agent 只读审查无阻塞问题；特别要求实际核对双宠首尾布局、侧头像目标及切换后三处身份一致，均已在开发工具中完成。本轮手机扫码仍待用户确认。
