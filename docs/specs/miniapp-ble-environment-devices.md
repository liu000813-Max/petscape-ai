# 小程序 BLE 温湿度设备

## 目标与体验

主人从当前选中的宠物家庭卡片添加 BLE 温湿度传感器。扫描页明确目标宠物，只列附近设备。连接后查看该宠物对应传感器的读数、读取时间和连接管理。设备入口继续留在首页宠物家庭区域；单宠详情展示相同设备状态，避免读数归属混乱。

连接和读数分开反馈。状态依次为未连接、扫描中、已连接并等待首读数、数据正常、数据陈旧或读取失败、已断开。页面只在成功解码并校验时间有效的温湿度样本后标示数据正常。蓝牙链路建立时以等待状态显示，读数过期时保留上次时间并标陈旧，不持续显示绿色实时状态。

配对步骤为初始化蓝牙、开始发现、用户选择设备、建立 BLE 连接、枚举服务和特征、订阅可通知特征或读取可读特征、验证样本后关联到当前宠物。取消、微信后台切换、蓝牙关闭和断连都要停止发现并更新界面；失败可手动重试。不得对未过滤的任何蓝牙设备自动连接。

## 首个设备协议范围

优先支持标准环境传感器 GATT 服务 `0x181A`，温度特征 `0x2A6E`，湿度特征 `0x2A6F`。先核对特征属性 `read`、`notify` 或 `indicate`，再选择读取或订阅，并按 Bluetooth SIG 定义解析字节、单位、分辨率和无效值。厂商自定义服务只有取得型号、UUID 表和数据编码规则后才增加适配。

读取的设备身份需采用设备上报的稳定标识。微信本次扫描的 `deviceId` 仅用于当前连接；如果硬件不广播稳定身份或没有可读序列号，重开应用时让用户重新选择设备，不从附近设备名称猜测。

## 手机、数据与验证边界

- 蓝牙操作须由主人明确点击开始。按需打开适配器和扫描，连接断开时提供重连入口，不在后台无限保活或无限重试。
- 当前产品定义未决定历史采样、跨手机同步、报警、订阅提醒和多个传感器之间的共享规则。首版界面显示本次有效读数及最后更新时间；这些额外能力不由 BLE 已连接推导。
- 保存宠物设备关联前，确认传感器的稳定标识、唯一性、重置和转让流程，以及它是否能只关联一只或多只宠物。原始广播和特征 payload 不进入客户端日志。
- BLE 不能靠微信开发者工具截图验收；需用真实传感器和至少一台 Android、一台 iOS 手机测试发现、连接、有效解码、断开、蓝牙关闭和重新连接。

## 配对前置资料

选择硬件后记录型号、说明书、是否标准 `0x181A`、稳定身份来源、读数刷新间隔、温湿度格式、量程、精度和单位。若设备使用私有 GATT 或广播包，需由厂商提供可实施的 UUID 与字节协议。没有实物时只评审 UI 状态，不宣称 BLE 接入或温湿度数据已完成。

草图审阅版的「宠境设备」从首页及单宠详情进入，按路由传入的宠物 ID 请求本人档案。界面标示未连接和配对待开放。身份校验失败时展示读取错误，避免把无权访问的档案显示为无设备。接入实物后再启用发现、连接和采样。
