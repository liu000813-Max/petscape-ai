# 小程序主人资料

用户确认点击“我的”身份卡进入编辑个人资料，支持头像、裁切、昵称保存；随后要求支持微信头像和昵称填写。其余页面布局不在本轮范围。

## 数据与接口

- `MiniappProfile` 以 `userId` 为唯一主键，关联当前账号；保存昵称及可空的 `avatarAssetId`。不修改 `User.name/image` 或历史社区署名，也不将宠物封面用作主人头像。
- `GET/PATCH /api/v1/profile` 目标只来自服务端会话。PATCH 严格接收 1–30 字昵称和可选头像资产 ID，不接收用户 ID、角色或远程图片 URL；昵称和头像一次原子保存。
- `POST /api/v1/profile/avatar-upload` 接收最多 10 MiB 的 JPG、PNG、WebP 二进制，先认证，再限制流式读取并校验真实魔数；经私有 OSS 写入与确认成为 `user_avatar`。只能绑定本人、已确认且种类正确的资产，不能借用其他账号或宠物封面。
- 资料响应只包含 `nickname/avatarAssetId/avatarUrl`，不含邮箱、手机号、微信标识或会话。头像 ID 持久保存，临时签名地址每次读取生成，使用 `private, no-store`。

## 原生交互

“我的”主人资料与宠物列表分别读取；其中一项失败不阻断另一项，旧结果不能覆盖最新读取。无昵称显示默认养宠人，读取失败不残留旧头像。

编辑页提供 `button open-type="chooseAvatar"` 入口，接收用户确认后的本地头像路径，保存前仅为草稿。昵称使用 `input type="nickname"`，支持微信快速填写及手动输入；提交通过原生 form 读取当前值，避免仅依赖 blur/input 的到达顺序。微信官方组件页面本轮不可读，保留官方链接供后续核实，不反复请求；原生选择界面是否可用以手机验收为准。

自定义选图沿用现有 1:1 裁切，保留原图供重裁；微信头像结果也可重裁。取消、裁切失败和读取失败保留之前草稿，成功重裁后清除已上传资产缓存。上传与绑定分开处理；绑定不明时锁编辑、同时回读核对昵称与头像 ID，两项一致才报告保存成功。读取仍失败则保留草稿和已上传 ID，要求显式核对，不自动重放写入。

## 发布

新增迁移通过空库、重复迁移及旧数据升级验收后部署独立小程序 API。Nginx 仅增加精确资料路径，11 MiB 限制仅在头像上传 location 生效，子路径显式配置 rewrite/proxy。后端健康、鉴权及真实读写验证后才交付使用新接口的开发预览码；微信选择头像和昵称仍需用户在手机确认。
