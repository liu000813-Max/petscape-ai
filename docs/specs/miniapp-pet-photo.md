# 小程序宠物头像上传

本轮实现用户为每只宠物上传照片，不是主人的个人账号头像。沿用宠物档案和 coverAssetId，不新增账号资料页面。

编辑或新建档案时可从相册、相机选择一张 JPG、PNG 或 WebP，最大 10 MiB。选图后进入微信原生 1:1 裁切，可拖动和缩放；确认后显示圆形头像预览。选择仅更新本地预览，点击保存后才上传。取消裁切保留此前草稿，撤销选择恢复此前头像。默认继续显示 PETSCAPE 物种图。

待保存的照片提供“重新裁切”，始终使用最初本地源图，避免反复裁切丢失画面。裁切期间锁定保存、选图和撤销。只读取裁切成功返回的新文件，并重新校验 MIME 和大小；取消、失败或新文件读取失败均不替换原草稿或已上传资产 ID。

原生裁切依据腾讯维护的 [API 类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)中 CropImageOption 与 wx.cropImage：最低基础库 2.26.0，使用 cropScale 为 1:1，读取 tempFilePath；本次官方文档网页无法打开，不反复请求。接口不存在时提示更新微信，不把未经裁切的原图当作成功结果。已保存的远程 OSS 图片不能直接传给裁切接口；本轮重新裁切仅针对当前本地所选照片。

新建档案先取得宠物 ID，再上传并绑定照片。照片失败时明确提示档案已保存，重试复用同一宠物。上传成功后暂存 assetId；绑定响应不明时先读取档案核对，重试不重复上传已成功的图片。失败保留此前头像，不自动重放网络失败。

现有 `/api/v1/pets/:id/cover-upload` POST 的 JSON 签名上传合同保留；新增同一路径的原始图片请求体。小程序通过已经配置的 HTTPS API 域名上传，使用当前会话。路由先鉴权并核实宠物归属，再逐块读取并限制体积；服务端核对图片头与 MIME，写入私有 OSS 后复核大小、类型和状态。只有 available 且同一主人的 pet_cover 可以绑定。旧客户端 Cookie 与小程序会话都有效。

Nginx 仅对此上传子路径放宽请求上限为 11 MiB；应用仍限制为 10 MiB，其他小程序 API 为 1 MiB。对象保持私有，档案返回短期签名图片地址；重新进入首页、列表和编辑页会读取新地址。没有存储配置时不能宣称上传可用。

不新增数据库表或迁移。不会删除历史照片或已有宠物；失败留下的 pending 对象不得作为头像显示。当前没有后台自动清理孤立照片的承诺。
