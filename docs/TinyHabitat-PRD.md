# TinyHabitat AI 产品需求文档

> 文档状态：2026-07-16 完成 Web V1 产品方向校准。
>
> 本文件是产品定位、用户承诺、Web V1 用户故事与范围边界的单一真相源。当前代码能力与黑客松交付历史以 `integration-mapping.md` 和实际代码为准。本版只定义产品层方向，具体实施方案在进入开发前另行讨论。

## 1. 产品定义

TinyHabitat AI 面向希望改善爬宠与小宠居住环境的用户，帮助他们把理想宠物空间中的原创物品，从 2D 灵感推进到可以确认、审核、报价、打印和交付的实物。

产品解决的核心问题是：用户能想象理想的宠物空间，却缺少把想象转化为真实物品所需的设计、建模、制造和安全判断能力。

### 1.1 一句话定位

把宠物空间效果图中真正想拥有的原创物品，推进到可制造、可报价、可交付的实物。

### 1.2 产品不是什么

TinyHabitat AI 不是单纯的 AI 生图工具、3D 建模工具或宠物用品商城。

- 2D 效果图帮助用户形成设计偏好和购买意愿。
- 3D 场景帮助用户确认比例、位置和空间关系。
- 制造审核决定一个候选设计能否进入正式报价与生产。
- 人工沟通、审核和履约是 Web V1 服务的一部分。

## 2. 目标用户与核心问题

### 2.1 目标用户

- 养爬宠与小宠，希望改善现有居住环境的用户。
- 重视宠物空间的审美、安全和适配，愿意为定制结果付费的用户。
- 喜欢通过小红书、抖音、B 站等平台分享宠物生活的用户。
- 有原创配件需求，但缺少设计、建模和 3D 打印知识的用户。

首发物种和具体使用场景尚未最终拍板。Web V1 先验证一条完整用户故事，不同时扩张多个物种和品类。

### 2.2 用户问题

- 很难想象普通笼箱可以被改造成什么样。
- 看到喜欢的效果图后，不知道图中的物品能否真实制作。
- 无法判断物品放进现有环境后的比例、位置和适配关系。
- 传统定制需要反复沟通、画图、建模和报价，过程不透明。
- 3D 模型能够显示或切片，不代表实物适合打印、安装和宠物接触。

## 3. Web V1 要验证的核心假设

Web V1 不以功能数量作为成功标准，而是验证下面这条行为链能否成立：

1. 用户会因为一张完整的 2D 宠物空间效果图产生明确偏好。
2. 用户会从图中选择一个真正想拥有的原创躲避屋。
3. 用户愿意继续进入 3D 场景确认比例、位置和整体关系。
4. 用户愿意为通过制造审核的方案提交定制申请并接受报价。
5. 审核通过的方案可以通过人工协作完成收款、打印、质检和交付。

第一笔真实收入对应一份经过用户确认和人工审核的定制制造方案，不是单独一张效果图或一个未经审核的 3D 文件。

## 4. 首发核心用户故事

> 作为一名希望改造宠物居住环境的用户，我想上传宠物和现有环境，描述喜欢的氛围，先看到完整的 2D 改造方案；当我喜欢其中一个原创躲避屋时，我可以选择它，在 3D 场景中确认它放进现有环境后的效果，然后提交制造审核和定制申请，获得正式报价，并最终把它制作出来。

首发只验证一个原创躲避屋，不承诺从效果图中选择任意物品，也不承诺一次制造整个场景。

## 5. 端到端竖切

### 5.1 理解宠物与现有空间

用户提供宠物、当前居住环境、空间限制、安全要求和期望氛围。产品需要让用户感到需求被理解，同时避免把体验变成工程参数表。

### 5.2 生成并选择 2D 整体方案

产品生成完整的 2D 环境方案，帮助用户判断是否喜欢这个方向、是否适合宠物、是否愿意继续深入。

用户体验顺序始终是先完成 2D 方案选择，再进入 3D 场景。2D 是主要决策界面，不承担制造承诺。

### 5.3 选择一个原创躲避屋

用户从满意的效果图中框选一个原创躲避屋，并表达希望保留的用途、主题和关键特征。

这个动作把“喜欢一张图”推进为“想拥有图中的这个物品”，是 Web V1 的核心转化节点。

### 5.4 在 3D 场景中确认

产品把原创躲避屋作为 3D 制造候选放进场景。用户确认其大小、位置、空间关系和整体效果。

3D 场景服务于购买确认，不需要成为专业建模工具。用户在这里确认的是候选方案，尚未获得生产批准。

### 5.5 提交制造审核

用户确认候选方案后提交制造审核。产品明确展示审核状态，并在需要时收集补充信息或发起人工沟通。

审核负责判断方案能否稳定打印、安装、清洁和供宠物安全使用。无法满足条件的方案需要调整，不直接进入报价与生产。

### 5.6 报价与定制申请

人工审核通过后，用户收到绑定已批准方案的正式报价，并提交定制申请和联系方式。

Web V1 不要求站内完成支付。具体收款方式可以由运营人员与用户人工确认。

### 5.7 人工生产与交付

运营人员完成人工收款、打印、后处理、质检和发货，并更新项目状态。用户可以回到项目查看当前进展。

## 6. 各阶段的用户承诺

| 阶段 | 用户获得什么 | 不代表什么 |
|---|---|---|
| 2D 效果图 | 整体设计方向和物品灵感 | 图中所有内容都能制造或 1:1 交付 |
| 3D 制造候选 | 比例、位置和空间关系确认 | 已经通过生产审核 |
| 制造审核中 | 方案已经进入人工可制造性判断 | 已形成最终价格或生产承诺 |
| 生产批准方案 | 可以正式报价和进入生产沟通 | 已完成支付、打印或发货 |
| 生产与交付 | 按批准版本完成制造和履约 | 整张 2D 场景被完整复刻 |

产品内部需要保持同一份结构化方案贯穿 2D 选择、3D 确认、制造审核和报价，避免在每个阶段重新解释用户需求。具体实现方式不在本版 PRD 中拍板。

## 7. Web V1 范围

### 7.1 必须包含

- 宠物、环境、空间限制和氛围需求输入。
- 完整 2D 环境方案生成与选择。
- 从效果图中选择一个原创躲避屋。
- 原创躲避屋的 3D 场景确认。
- 制造候选与人工审核状态。
- 审核通过后的正式报价。
- 定制申请与联系方式提交。
- 人工收款、生产、质检和发货的状态更新。

### 7.2 辅助体验

- 宠物 Avatar 可以作为传播内容、辅助体验或首单礼物保留。
- 分享图可以帮助传播，但不阻塞核心成交链。

辅助体验不得成为核心用户故事完成的前置条件。

### 7.3 非目标

- 从效果图中选择任意类型的物品。
- 一次制造完整宠物场景。
- 全自动判断并直接生产。
- 专业级 3D 建模与编辑工具。
- 标品商城、完整购物车和站内支付。
- 自动排产、物流对接和完整售后系统。
- 用户社区和公开作品广场。
- 同时支持大量物种、场景和原创品类。
- iOS App 和微信小程序首发。
- 把宠物 Avatar 作为主商品路径。

## 8. 成交与服务边界

### 8.1 首发成交对象

首发成交对象是经过用户确认和人工审核的原创躲避屋定制方案。正式报价应对应同一份已批准方案。

### 8.2 人工服务边界

Web V1 采用前台产品化、后台人工履约：

- 产品负责收集需求、帮助选择、组织确认过程并展示状态。
- 人工负责制造判断、必要的方案调整、正式报价、收款、生产和交付。

完整支付、物流和自动排产可以后置，人工履约不是临时兜底，而是首发服务设计的一部分。

## 9. 成功标准

### 9.1 核心漏斗

- 用户完成需求输入并获得 2D 方案。
- 用户明确选择一个原创躲避屋。
- 用户进入 3D 场景并确认候选方案。
- 用户提交制造审核和定制申请。
- 候选方案通过人工审核。
- 用户接受正式报价并支付定金。
- 实物完成交付。

### 9.2 质量标准

- 用户能区分 2D 灵感、3D 候选和生产批准方案。
- 正式报价绑定用户确认且审核通过的方案。
- 实物与批准方案在造型、尺寸和用途上保持一致。
- 无法制造或不适合宠物使用的候选不会直接进入生产。
- 用户能够理解人工审核、沟通和履约所需的等待。

Web V1 最核心的验证指标是：有多少用户愿意把“喜欢一张图”推进到“愿意为图中的这个原创物品付钱”。

## 10. 关键风险

- 用户可能把 2D 效果图理解为最终实物的 1:1 承诺。
- 原创造型可能缺少真实尺寸、隐藏结构、安装关系和安全信息。
- 3D 候选可能看起来合理，但无法稳定打印、安装或清洁。
- 不同宠物对材料、结构和接触安全的要求不同。
- 人工审核和调整时间可能影响用户预期。
- 用户可能喜欢效果图，但不愿继续提交审核或接受报价。
- 实物与用户确认版本之间的落差会直接影响信任。

## 11. 待讨论的产品决策

- 首发物种及其最典型的居住环境。
- 原创躲避屋需要解决的首个具体使用问题。
- 用户在 2D、3D 和人工审核阶段分别需要看到哪些信息。
- 定制申请、定金和正式报价之间的关系。
- 人工审核与用户沟通的服务标准。
- 首批真实用户从哪里获得，以及如何验证付费意愿。

这些问题在进入实施讨论前继续收敛。本版不写入具体技术方案、工期或开发批次。

## 12. 未来扩展方向

以下方向保留为未来候选，不构成 Web V1 承诺：

- 标准模块及其受约束变体。
- 更多原创物品类别。
- 多模块组合与整装场景。
- 用户账号、长期宠物档案和复购记录。
- 完整支付、订单、排产、物流和售后。
- 分享、晒单和用户社区。
- iOS App 与微信小程序。

多端形态共享同一套产品定义：用户从灵感形成意愿，经确认和审核进入真实制造交付。客户端形态不改变这条核心承诺。

## 13. 与当前黑客松版本的关系

当前仓库保留宠物 Avatar、AI 环境效果图、3D 场景、模块展示和切片下载等黑客松能力。这些能力证明了部分技术链可以运行，但不等于 Web V1 的商业闭环已经成立。

历史批次规格、验证报告和研究材料继续记录“当时做了什么”。它们不自动定义获奖后的产品方向。Web V1 的功能与实施方案需要从本 PRD 的核心用户故事重新推导。
