# PetScape 领域词典

本词典只定义跨模块需要稳定理解的业务语义。它不复制字段、枚举、接口 shape 或当前进度；实现细节以 Prisma schema、Zod contract、migration 和代码为准。

| 术语 | 它承诺什么 | 它不代表什么 |
|---|---|---|
| Project | 用户拥有的设计工作空间，用来组织从想法到可报价输入的过程。 | 不是生成、审核、支付、生产和物流的万能状态机。 |
| DesignItem | Project 中一个可被持续设计、确认并选作交易目标的物品身份。 | 不是场景里的某次摆放，也不是某个模型文件或已售商品。 |
| ModelConfirmation | 用户对某个 DesignItem 的特定模型引用和尺寸结果作出的不可变确认。 | 不证明模型可制造、对宠物安全、已放入场景或可以报价。 |
| Scene | 用户持续编辑的空间草稿，组织笼舍、目标物品和其他参照物的摆放关系。 | 不是用户已确认的证据，也不冻结后续审核或交易输入。 |
| SceneConfirmation | 用户对一个场景版本、目标物品实例及其已确认模型作出的不可变快照。 | 不等于制作与安全审核通过，也不承诺价格、付款或交付。 |
| CustomizationRequest | 用户基于 SceneConfirmation 提交的定制申请版本，冻结审核所需的目标、产品、材料与说明语境。 | 不是审核结果、报价、订单；修改后重提应形成新版本，而非抹去历史。 |
| CheckRun | 对一个定制申请快照执行的可审计制作与安全审核。 | 不保证绝对安全，也不自动产生价格承诺；不确定结果必须保留为不确定。 |
| Quote | 服务端基于特定申请、审核、估算、材料和定价规则形成的有期限价格承诺。 | 不是付款成功、订单成立或一定能够履约；沙箱 Quote 不能用于真实成交。 |
| DeliveryAddress | 某个已接受 Quote 在结算时使用、可版本化并需重新确认的当前收货信息。 | 不是订单中的永久地址证据；Order 成立时会另行冻结地址快照。 |
| PaymentIntent | 围绕一个 Quote 发起和恢复付款过程的记录，绑定服务端金额与已确认地址快照。 | 不是支付成功证明；只有可信、已验证的渠道结果才能推进后续承诺。 |
| Order | 从可信付款成功结果创建的购买记录，冻结商品、价格、审核与地址等成交语境。 | 不是生产或物流本身；订单成立不等于已经制造、发货或完成交付。 |

## 使用规则

- 讨论跨模块边界时先使用这些名字，不另造含义相近但承诺不同的缩写。
- 术语含义改变时，先确认这是产品或架构决定，再更新对应正本与本词典。
- 新增字段或状态时只改实现正本；除非它改变了一个术语的业务承诺，否则不更新本词典。
